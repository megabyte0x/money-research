## Why a proposal label can be misleading

The checked ZIP index still called NU6.2 the latest settled upgrade while other deployment sources confirmed NU6.3 activation. ZIP 258 displayed “Draft,” and ZIP 2005 and ZIP 1016 displayed “Proposed,” despite deployment evidence for associated changes. The correct method is to inspect the **specific feature**, its deployment rules, and dated implementation evidence—not to assume everything in a document is live or nothing is live based solely on its header.

The same applies to old plans that used “NU7” for work later delivered as NU6.3. A roadmap's label or target date is not a reliable substitute for an activation record.

## The hypothetical timeline has gates instead of promises

Legal preparation → useful private payments → retained working balances → native contracts → fiscal denomination → broader standard.

Every arrow is conditional. A society can pause indefinitely, adopt only some functions, or exit. No date for global ZEC adoption is asserted.

## Key takeaways

Use event dates and deployment records. Treat roadmaps, live status, and hypothetical adoption as separate categories, especially after the rapid 2026 security changes.
